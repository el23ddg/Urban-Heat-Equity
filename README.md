# 🌆 Urban Heat Island & Green Equity Spatial-Data Analyzer

**Problem:** Concrete absorbs and re-radiates heat; trees and green space cool
the air through shade and evapotranspiration. But green space is rarely
distributed equitably across a city — and the neighborhoods with the least
of it are often the ones least able to afford air conditioning during a
heatwave. This project quantifies that inequity and predicts which
neighborhoods are most heat-vulnerable, using open geospatial tooling and a
simple, explainable regression model.

## What this does

1. Loads neighborhood polygons (postal-code / district level) as a
   GeoDataFrame and standardizes their coordinate reference system.
2. Engineers a **Green Equity Index** = Green Cover Area ÷ Built-Up Area for
   every neighborhood.
3. Runs EDA — summary statistics + a correlation heatmap linking green
   cover, population density, and building height to surface temperature.
4. Trains two regression models (Linear Regression, Random Forest) to
   predict **temperature anomaly** from the Green Equity Index, population
   density, and building height, and reports feature importance.
5. Produces:
   - an **interactive Folium map** color-coded by predicted temperature
     anomaly, with a tooltip per neighborhood (`outputs/heat_equity_map.html`)
   - a **static Seaborn scatterplot** of green cover vs. temperature anomaly
     (`outputs/green_vs_temp.png`)
   - a correlation heatmap and feature-importance chart
   - a CSV of the full enriched dataset + a JSON of model metrics

## Quickstart — running it locally in VS Code

### 1. Prerequisites
- Python 3.10–3.12 installed (check with `python3 --version`)
- VS Code with the **Python extension** (Microsoft) installed
- Git (optional, only if you're pushing this to GitHub)

### 2. Get the project onto your machine
Either clone your GitHub repo after you push this code, or just unzip/copy
this folder to somewhere like `~/projects/urban-heat-equity`.

### 3. Open it in VS Code
```bash
cd urban-heat-equity
code .
```

### 4. Create and activate a virtual environment
Open a terminal **inside VS Code** (`` Ctrl+` `` / `` Cmd+` ``):

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

**Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Once activated, your terminal prompt should show `(.venv)`. In VS Code, also
select this interpreter: `Ctrl+Shift+P` → *"Python: Select Interpreter"` →
choose the one inside `.venv`.

> **Note on geopandas:** on Windows, `geopandas`/`shapely`'s underlying GEOS
> library occasionally needs `pip` to pull prebuilt wheels rather than
> compiling from source. If `pip install` fails with a compiler error, run
> `pip install --upgrade pip` first, or install via conda instead:
> `conda install -c conda-forge geopandas` in an Anaconda/Miniconda prompt.

### 5. Install dependencies
```bash
pip install -r requirements.txt
```

### 6. Generate the synthetic dataset (only needed once, or to regenerate)
```bash
python src/generate_data.py
```
This writes `data/neighborhoods.geojson` — 36 synthetic districts arranged
in a 6×6 grid, each with green cover %, building %, population density,
average building height, and a physically-motivated (noisy) temperature
anomaly.

### 7. Run the full analysis
```bash
python src/main.py
```

You should see console output like:
```
=== Model performance (held-out test set) ===
LinearRegression: R^2 = 0.991, MAE = 0.263 degC
RandomForest: R^2 = 0.865, MAE = 0.750 degC
```
(exact numbers will vary slightly by scikit-learn version, but the
*direction* of every effect — more green = cooler, taller/denser built form
= hotter — is stable because it's baked into the synthetic ground truth.)

### 8. View the outputs
- Open `outputs/heat_equity_map.html` directly by double-clicking it (opens
  in your default browser), or right-click it in VS Code's file explorer
  and choose **"Open with Live Server"** / **"Reveal in File Explorer"**.
- Open the `.png` files in VS Code's built-in image viewer or your OS's
  photo viewer.
- Open `outputs/neighborhood_metrics.csv` in VS Code (or Excel) to see the
  full per-neighborhood table, including predicted temperature anomalies.

### 9. Debugging in VS Code (optional but handy)
Create `.vscode/launch.json` with:
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Run main.py",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/src/main.py",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    }
  ]
}
```
Then just hit **F5** to run with breakpoints.

## Using real data instead of the synthetic city

`src/fetch_real_data.py` replaces the synthetic grid with real data for an
actual city using free Google Earth Engine datasets, writing a
`data/neighborhoods.geojson` in the same schema — so `main.py` and the
notebook work unchanged afterward.

### Step 1 — Get real neighborhood boundaries
The one piece Earth Engine can't give you: a GeoJSON of neighborhood/ward/
postal-code polygons for your city, with at least a name column.

- **Overpass Turbo** (easiest, no account needed):
  1. Go to https://overpass-turbo.eu/
  2. Run a query like:
     ```
     [out:json][timeout:60];
     area["name"="YOUR_CITY"]->.searchArea;
     relation["boundary"="administrative"]["admin_level"="10"](area.searchArea);
     out geom;
     ```
     `admin_level` varies by country (try 8, 9, or 10 until you get
     neighborhood-sized polygons rather than the whole city as one blob).
  3. Click **Export -> GeoJSON**, save it as
     `data/real_neighborhoods_raw.geojson`.
- **Alternative:** search "`<your city>` open data GIS neighborhoods
  geojson" — many cities publish these directly (cleaner than OSM).
- Open the file and note the exact column name holding each neighborhood's
  name (e.g. `"name"`, `"NAME"`, `"ward_name"`) — needed in Step 3.

### Step 2 — Set up Google Earth Engine
1. Go to https://code.earthengine.google.com/ and sign in with a Google
   account (free).
2. First-time sign-up walks you through creating a **Cloud Project** — any
   name works, e.g. `urban-heat-equity`. Note the **project ID** shown.
3. Locally, in your activated virtual environment:
   ```bash
   pip install earthengine-api geemap
   earthengine authenticate
   ```
   This opens a browser, you log in, and it stores credentials locally —
   one-time setup.

### Step 3 — Edit the config block in `src/fetch_real_data.py`
```python
EE_PROJECT = "your-gee-project-id"                  # from Step 2
RAW_BOUNDARIES_PATH = "data/real_neighborhoods_raw.geojson"  # from Step 1
NAME_FIELD = "name"                                  # the column from Step 1
SUMMER_START = "2025-06-01"                          # your city's hot season
SUMMER_END = "2025-08-31"
```

### Step 4 — Run it
```bash
python src/fetch_real_data.py
```
This queries, per neighborhood polygon:
- **Dynamic World** (10m land cover) -> `green_cover_pct`, `building_pct`
- **MODIS LST** -> real land-surface temperature -> `temp_anomaly_c`
  (each polygon's temperature minus the city-wide average, so it's a
  genuine anomaly, not an absolute reading)
- **WorldPop** -> `population_density_km2`
- **GHSL building height** -> `avg_building_height_m`

It writes the result to `data/neighborhoods.geojson`, overwriting the
synthetic version. First run on a new city can take a minute or two —
Earth Engine is aggregating real satellite imagery server-side per polygon.

### Step 5 — Re-run the existing analysis, unchanged
```bash
python src/main.py
```
or re-run the notebook. The Green Equity Index, both regression models, the
correlation heatmap, and both visualizations all work exactly as before —
except now every number is real.

### Notes and caveats
- **Dynamic World** "green" = trees + grass + crops + flooded vegetation.
  If your city has unusual land cover (desert, heavy agriculture at the
  edges), sanity-check a few neighborhoods against satellite imagery in
  Google Maps before trusting the numbers.
- **MODIS LST** is 1km resolution — good for city-wide patterns, too coarse
  to distinguish neighborhoods only a few blocks apart. For finer
  resolution, swap in Landsat 8/9 thermal bands (~30m) in
  `compute_lst()` — same code structure, different Earth Engine collection.
- If a small polygon sits right at a tile boundary, a query occasionally
  returns `None` for it; the merge will show `NaN` — just re-run, or
  slightly increase `scale=` for that layer.

## What the (synthetic) results show

- **Green Equity Index is the strongest single predictor of neighborhood
  heat** (correlation ≈ ‑0.94 with temperature anomaly) — far stronger than
  population density alone.
- In the Random Forest model, **building height/density** edged out
  population density in feature importance — suggesting the *physical form*
  of a neighborhood (how much heat-trapping mass and impervious surface it
  has) matters at least as much as how many people live there.
- Both models agree on direction: every neighborhood with a Green Equity
  Index above ~1.5 (i.e., more green area than built area) sits below the
  city's average temperature; every one below ~0.5 sits above it.

*(Re-run against a real city's data to get real headline numbers before
publishing — treat the above as a description of the method, not a claim
about any actual city.)*
